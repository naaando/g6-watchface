## G6 connection finding (2026-09-27)

The user removed the G6 from AuraFit and factory-reset it to make it discoverable to another app. In pairing mode, the official JieLi Watch Test Tool found the G6 and completed RCSP initialization over BLE. Its log identified the JieLi watch SDK flag. The tool then disconnected because its `WatchManager` requires mandatory-upgrade or external-flash-transfer support for its watch operations, and the G6 reported neither. This limits the **test tool's** watchface browser/transfer path; it does not imply the G6 cannot use custom dials through AuraFit's own path. The tool automatically synchronized the time during connection. No watchface file or firmware was transferred. After that app could not handle watch operations, the user paired the G6 with AuraFit again; AuraFit's device page then showed the G6 connected with 62% battery.

Reproduce a local decode with Python, Pillow, and NumPy:

```sh
python Fogg/comp_decomp.py trek-watchfaces/0.0_AM05_G6_11359.bin trek-watchfaces/decoded_11359
python Fogg/comp_decomp.py trek-watchfaces/0.0_AM05_G6_11448.bin trek-watchfaces/decoded_11448
```
